# D2 v1 developer guide

D2 v1 is a Rust library for a trusted-source exact-Script derived-state
handoff. It exports one exact packed Script plus role, its typed derived rows,
and the referenced transaction closure into a deterministic artifact. A
destination light client validates its own chain authority and atomically
imports the artifact while retaining authority for headers, consensus,
reorgs, and future filtering.

The supported upstream profile is:

```text
ckb-light-client@12e29522ab7e078ada704d4ac04cbc0498009b7b/storage-v1
```

The initial native backend feature builds are `rocksdb` (default) and
`sqlite`. The semantic artifact is backend-neutral; adapters write native
backend state and never copy database files.

## When to use D2

Use D2 when a trusted source has already indexed one exact Script through a
handoff height H and a supported destination should obtain that derived view
without reconstructing the same tested historical Script view through H.

D2 is useful for controlled backend changes, restore workflows, and future
embedded-client integrations. The repository does not claim a deployed Pocket,
Neuron, or Fiber integration.

## Basic operation shape

The exact storage constructor is selected by the Cargo feature build:

```rust,ignore
use d2_script_handoff::{D2, ScriptRole, UpstreamAdapter};

// In a RocksDB build:
let storage = d2_script_handoff::RocksDbStorage::new(path);
// In a SQLite build use `SqliteStorage` instead and compile with
// `--no-default-features --features sqlite`.
let adapter = UpstreamAdapter::new(storage, path);
let d2 = D2::new(adapter);

let exported = d2.export(&packed_script_bytes, ScriptRole::Lock)?;
std::fs::write("handoff.d2", &exported.bytes)?;
```

At the destination, the client must already have independently established the
same genesis and the block hash at H:

```rust,ignore
let storage = d2_script_handoff::RocksDbStorage::new(destination_path);
// Use `SqliteStorage` in the SQLite feature build.
let adapter = UpstreamAdapter::new(storage, destination_path);
let d2 = D2::new(adapter);

let bytes = std::fs::read("handoff.d2")?;
let inspection = d2.inspect(&bytes)?; // no destination mutation
let validation = d2.validate(&bytes)?; // authority and conflict checks
let result = d2.import(&bytes)?;       // offline/exclusive atomic import
```

`D2::import` validates the complete owned artifact, binds H and its hash to
destination authority, and commits Script-derived rows, transaction closure,
the exact Script registration/cursor, and destination-local scheduler metadata
through the native backend transaction.

Repeated identical imports are idempotent. Conflicting rows, stale progress,
wrong identity, wrong role, wrong genesis, wrong handoff hash, missing closure,
unsupported profiles, malformed artifacts, and live/exclusive lifecycle
violations fail closed.

## Lifecycle requirement

Export and import are quiescent operations. D2's adapter takes an advisory
exclusive lock for export/import. Integrated protocol/filter/synchronizer/
relayer workers must hold the adapter's `acquire_protocol_activity()` guard
while they can mutate the destination. Import rejects while that guard is
active, and competing D2 importers cannot both acquire the OS-level exclusive
lock.

The guard is the enforceable boundary for D2-integrated workers. D2 cannot
introspect arbitrary code that mutates the same database without using the
supported adapter lifecycle.

After import, close/reopen the client before restarting normal protocol
workers. A successful import is ordinary destination state: subsequent
filtering, spends, proofs, and reorg rollback remain owned by the light client.

## Artifact semantics

The current format version is `1`. The canonical binary artifact contains:

- D2 magic and format version;
- upstream adapter/profile identifier;
- genesis hash;
- exact packed Script bytes;
- Script role;
- handoff height and block hash;
- cursor, equal to H in v1;
- canonical Script index rows;
- canonical transaction-index rows;
- exactly the referenced transaction closure;
- a CKB Blake2b-256 integrity digest.

The wire layout is fixed for format version 1: 8-byte magic `D2SHAND1`,
little-endian `u32` format version, length-prefixed profile, 32-byte genesis,
length-prefixed packed Script, one role byte (`0` lock / `1` type),
little-endian `u64` handoff height, 32-byte handoff hash, little-endian `u64`
cursor, then three counted row sections. Each row is a length-prefixed key
followed by a length-prefixed value; rows are strictly sorted by key within a
section. The final 32 bytes are the Blake2b-256 digest of all preceding bytes.
Unknown versions, trailing bytes, duplicate/noncanonical rows, malformed
lengths, and limit violations are rejected.

The default safety bounds are a 64 MiB complete artifact, 64 KiB Script, 256
bytes profile, 1,000,000 rows per Script-index section, 100,000 transaction
closure rows, and 4 MiB per row key/value. Callers may select stricter bounds;
raising them is a deployment decision and is not a mainnet-scale guarantee.

Backend name, process identity, timestamps, signatures, remote-provider
identity, consensus state, headers, peer state, global minimum from the source,
and PV1 interval coverage are not semantic artifact fields.

## Trust model and non-claims

D2 trusts the source to report its derived Script state and cursor honestly.
The destination independently validates structure, digest, identity, genesis,
H, closure, conflicts, and lifecycle, but cannot detect a source that omits
historical Script matches or overstates its cursor while remaining internally
consistent.

D2 v1 is not:

- a trustless historical completeness proof;
- a full light-client snapshot;
- a consensus-authority transfer;
- a wallet-secret or application-cache backup;
- a PV1 coverage ledger;
- a live importer;
- an arbitrary-version migration tool;
- a signed public snapshot distribution system.

## Errors and result semantics

The public error categories distinguish permanent artifact/contract rejection
(`MalformedArtifact`, `UnsupportedFormat`, `UnsupportedProfile`, identity,
genesis, handoff, closure, conflict, stale state, and invariant errors) from
retryable environment failures (`Lifecycle`, `Storage`, and `ResourceLimit`).
Successful results report the exact Script, role, accepted H/hash, row counts,
digest, cursor boundary, and whether the operation was idempotent.

The library has no CLI in v1. A caller supplies an already-open supported
upstream storage object, writes or transports the returned bytes, and calls
`inspect`, `validate`, and `import` at the destination. The caller must close
the client and restart its normal workers after import.

## Compatibility

Unknown D2 format versions and unsupported upstream adapter profiles fail
closed. Automatic migration across arbitrary `ckb-light-client` storage
versions is not supported. A future profile or format may add explicit
conversion, but it must not be inferred from matching raw bytes.
